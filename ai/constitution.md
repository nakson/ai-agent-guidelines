# Constitution（永远遵守）

> 跨任务硬约束，控制在 20 条内。细节见各专章；本页不讲故事。  
> Agent：任何任务开始前扫一眼；与专章冲突时以更具体专章为准，本页管「口味底线」。

## 必须

1. **先读实现再改**：读调用链、测试与数据约束，不只读需求/口述。
2. **最小改动**：只改任务所需；不顺手重构、不格式化未动文件。
3. **可验收**：写清做了什么、怎么验证；交代未验证项。
4. **不编造**：核对不到的 API / 表名 / 路径 / 配置键，不写成已有事实。
5. **二义性先标**：业务不清时列假设与待确认，不写死权限、审批、阈值。
6. **服务端鉴权**：身份、能力、租户与资源归属在服务端校验；不信任前端藏按钮。
7. **参数化与无密钥入仓**：查询参数化；不硬编码密钥口令。
8. **高风险要人审**：权限、审批状态机、并发、迁移、加密、跨租户、生产基础设施——提示独立审查，Agent 不自批合入。
9. **按风险选测**：改完跑相关测试 / lint；覆盖率找空白，不作唯一目标。
10. **规范按需引用**：写文档读 `ai/tech-writing.md`；写代码读 `ai/coding.md`；对口坑读 `ai/pitfalls/*`——不全量灌进上下文。

## 禁止

1. 只靠文档/自述判定「完成」
2. 为追 100% 覆盖率写低价值测试
3. 按文件大小机械拆微服务或碎片化文件
4. 把聊天长文未经蒸馏塞进本库
5. 事事 alwaysApply，让无关规则互相打架
6. 在业务仓复制本库全文（只留短指针）
7. 指针写本机绝对路径当权威
8. 交付思考过程代替可检查产出

## 自检（每个任务收尾）

- [ ] 改动是否最小且与任务对齐？
- [ ] 有无编造未核对的标识符？
- [ ] 相关测试 / 自检是否已跑或已声明未跑？
- [ ] 是否读了对口专章而非整库？
