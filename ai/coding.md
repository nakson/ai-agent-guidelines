# 写代码通例（AI Agent）

> 何时使用：实现功能、修 bug、改接口、动共享组件时先读。  
> 永远遵守的底线见 `ai/constitution.md`；本文件管编码通例。  
> 具体坑（React effect、i18n 源文件等）见 `ai/pitfalls/`。

---

## 必须

1. **改前读齐**：实现、调用方、测试、相关配置；不要只按文件名猜测。
2. **最小差分**：只改必要逻辑；不做无关重命名/格式化/「顺便清理」。
3. **与现有风格一致**：沿用项目分层、命名、错误处理与日志习惯。
4. **边界早返回**：单一职责；复杂分支先校验再干活。
5. **异步可失败**：网络/IO 有错误路径；React 等注意卸载与过期响应。
6. **状态单写者**：同一真相源（本地 state / 全局 store / 服务端）选一个；跨层同步有明确方向。
7. **安全默认**：鉴权在服务端；用户输入校验；密钥与口令不进代码与提交。
8. **改完验证**：跑相关测试 / 编译 / lint；在回复里写清结果与未验证项。

## 禁止

- 编造不存在的 API、表、配置键、事件名
- 在 `setState` updater / 纯函数里夹带副作用（dispatch、写 storage、调外部 setState）
- 「整表替换」用闭包旧数据覆盖异步返回后的新列表
- 扩大 effect 依赖却不审计回调是否会用旧索引/旧值回写父层
- 只改生成物、不改唯一源（如只改 locale JSON 而项目规定 CSV 为源）
- 无独立部署/扩缩/故障隔离收益时硬拆微服务
- 用前端隐藏控件代替鉴权
- 未获明确要求时 `git commit` / `git push`

## 反面 → 正面

| 旧 | 新 |
|----|----|
| 按口述直接开写 | 先打开实现与调用链，确认约束再改 |
| 「顺便」重构周边 | 只提交任务所需差分 |
| 猜一个 REST 路径写上 | 在 Comm/Resource/DAO 或 OpenAPI 里核对后再用 |
| effect 依赖一加，回调照旧通知父组件 | 依赖扩大后重审：只在本地真值变化时通知；旧索引不回写 |
| 注释写「为什么显而易见」的废话 | 只在 WHY 非显而易见时写短注释 |
