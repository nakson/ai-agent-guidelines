# 坑：改生成物 locale，不改文案唯一源

## 何时使用

项目约定「单一文案源 → 生成 locale JSON」（常见为 CSV / 表格 → `yarn i18n` 等）时，新增或修改 UI 文案必读。

## 典型错因

只改 `src/locales/*.json`（或只在代码里写 `t("key") || "English fallback"`），不入库唯一源。下次生成覆盖改动，或其它语言/环境缺失 key，表现为「我明明改过文案又没了」。

## 必须

1. **文案只写入项目规定的唯一源**（如 `dev/i18n.csv`，列含各语言）。
2. **改源之后跑生成命令**（如 `yarn i18n`）再提交生成物（若仓库跟踪生成物）。
3. 代码用 `t("key")`；新 key 与源文件同步入库。

## 禁止

- 直接手改生成出的 `*.i18n.json` / locale JSON 当作完成
- 只写代码 fallback 文案却不入库
- 假设「只改 en 就够了」而漏其它语言列

## 反面 → 正面

| 旧 | 新 |
|----|----|
| 打开 `zh_cn.i18n.json` 改一句 | 在 CSV（或项目唯一源）加行 → 跑生成 |
| `t("foo") \|\| "Save"` 且 CSV 无 `foo` | CSV 补齐各语言 → `t("foo")` |

## 自检

- [ ] 唯一源是否已有该 key 且各语言列齐全？
- [ ] 是否已跑项目的 i18n 生成命令？
- [ ] 是否未把手改生成 JSON 当唯一修改？

## 本仓路径

具体 CSV 路径与命令以**业务仓**规则为准（例如 INAV：`org.astri.inav.web/web/dev/i18n.csv` + `yarn i18n`）。
