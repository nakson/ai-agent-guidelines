# ai-agent-guidelines

> 中文可称：**AI Agent 使用指南库**  
> 本机路径：`/root/ai-agent-guidelines`  
> （原名 `org-standards` 已弃用：太像「公司制度」，看不出是给 AI Agent 用的。）

团队共用、**工具无关**的 Agent 可读规范与踩坑沉淀。Cursor / Copilot / Claude Code 等都能靠短指针引用同一套内容。

---

## 目的

让 AI Agent **读这份材料后，尽快产出符合我们专业标准（和已标定偏好）的结果**，少胡写、少重复踩已踩过的坑。

覆盖范围会随经验增长，不限于写文档，也包括：

- 写代码、改代码的约束与口味
- 更细的主题（如 React effect、i18n、文档开篇粒度……）
- 真实事故蒸馏出的「禁止再做 X」

最终形态：Agent 按任务打开对口章节 → 按必须/禁止/自检执行 → 输出可验收。

---

## 方向（对的）与原则

**方向是对的**：把标准与踩坑沉淀成可触发的机构记忆，是团队用 Agent 的高杠杆做法。

正确做法是 **蒸馏成分层、可触发、可检查的短规则**，不是堆一本越来越厚的圣经。

| 原则 | 含义 |
|------|------|
| **一份权威正文** | 通则与坑只在本库维护；业务仓不复制全文 |
| **短指针挂钩** | 各工具入口只写「去读哪个相对路径」 |
| **按需触发** | 写文档挂写作规范，写 React 挂 effect 规范；禁止事事 always-on |
| **可检查** | 必须 / 禁止 / 自检清单；优先「反面 → 正面」 |
| **靠 Git 对齐** | 换机器、换云端 Agent，靠 clone/pull；不靠本机绝对路径或个人全局规则当权威 |
| **能升就升** | 能变成测试 / lint / CI 的，升自动化；文档只留自动化盖不住的判断 |

## 怎么使用

### 1. 维护本库（加人经验时）

1. 先判断：这是**通例**还是**一次性故事**？
2. 通例 → 写入对应专章（或新建 `ai/xxx.md` / `ai/pitfalls/yyy.md`），写成：
   - 适用场景（何时读）
   - 必须 / 禁止
   - 反面 → 正面（最好有）
   - 自检清单
3. 能自动化的 → 同时补测试或 lint，规范里只留一句「以 xxx 测试为准」。
4. **改完只改本库**；业务仓指针路径不变则不用改业务仓。

### 2. 业务仓引进（三选一）

| 方式 | 做法 | 引进后路径示例 |
|------|------|----------------|
| **Submodule（多仓推荐）** | `git submodule add <本库 URL> docs/ai-agent-guidelines` | `docs/ai-agent-guidelines/ai/tech-writing.md` |
| **发布拷贝** | CI/脚本按 tag 同步进业务仓并开 PR | 同上或 `docs/ai/...` |
| **本机 symlink** | `ln -s /root/ai-agent-guidelines <业务仓>/docs/ai-agent-guidelines` | 同上；**指针里勿写 `/root/...`** |

### 3. 挂钩（引进后做一次）

从 `hooks/` 取对应 snippet，粘进业务仓，并把路径改成上表相对路径：

| 工具 | 挂到 |
|------|------|
| 通用 / 多种 Agent | 根目录 `AGENTS.md` |
| Claude Code | 根目录 `CLAUDE.md` 一小节 |
| Cursor | `.cursor/rules/*.mdc`（`globs` 按任务，正文外置） |
| GitHub Copilot | `.github/copilot-instructions.md` |

对话兜底：`@docs/ai-agent-guidelines/ai/tech-writing.md`（或对口专章）。

### 4. 日常派活给 Agent

- 说清任务 + 验收标准；需要时 `@` 对口专章，或依赖已配好的 globs/指针自动带上。
- 改完要求 Agent **过该专章自检**；有测试则跑相关测试。

### 5. 与业务仓特有规则的分工

| 内容 | 放哪 |
|------|------|
| 跨项目仍成立的写法、坑、口味 | **本库**专章 |
| 某产品分类、术语附录、仓库特例 | 业务仓短文件；本库可一句引用 |
| `globs` / `alwaysApply` | 仅业务仓 `.cursor/rules` 等工具适配层 |

## 避免什么（走歪的信号）

| 避免 | 为什么 |
|------|--------|
| **一本巨型 MD 什么都塞** | 上下文稀释，规则「都看见了」却都不严格执行 |
| **只写正确宣言，不写坑** | 旧错会原样再犯；要有禁止项与反面例子 |
| **事事 alwaysApply** | 写文档的规则干扰写代码，互相打架 |
| **只堆积聊天记录式长文** | Agent 需要 3～7 条可执行约束，不是故事全文；先蒸馏再入库 |
| **只靠文档、不跑验收** | 规范挡不住胡写；测试 / lint / 自检要一起用 |
| **规范当银弹、取消人审** | 权限、并发、迁移、跨租户等仍要人审 |
| **业务仓复制全文** | 多份副本必然漂移；只留指针 |
| **指针写本机绝对路径** | 换机器 / 云端 Agent 必挂 |
| **只增不删** | 过时规则比没有更糟；失效就删或归档 |

走歪的标志只有一个：**规范越来越厚，Agent 却还在犯同一类错。**

```markdown
| …  | …  |

- [ ] …
```
